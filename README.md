## 🔍 The headline from each

<details>
<summary><b>🕵️ PaySim — 97.7% of fraud caught, zero false positives</b></summary>

<br>

| | |
|:--|:--|
| **Rows** | 6,362,620 mobile-money transactions |
| **Status quo** | Existing rule caught 16 of 8,213 fraud cases — 0.2% recall |
| **Naive fix** | 66.6% recall, but 1,192,198 false positives (~218 false alarms per fraud caught) |
| **Shipped** | One behavioural signal — sender's balance drained to zero — **97.7% recall, 0 false positives** |
| **Stack** | Python → PostgreSQL views → Power BI |

➡️ **[Read the full analysis](https://github.com/Plensia/PaySim-Fraud-Analysis)**

</details>

<details>
<summary><b>🏭 Maven Fuzzy Factory — 1.2M+ rows, containerized end to end</b></summary>

<br>

| | |
|:--|:--|
| **Pipeline** | Incremental ETL into PostgreSQL, `created_at` watermark, primary-key validation |
| **Modelling** | 5 dbt marts — channel performance, product profitability, refund trends, cohort retention, order value |
| **Delivery** | Streamlit executive dashboard |
| **Ops** | Docker Compose, reproducible from a single `up` |

➡️ **[See the stack](https://github.com/Plensia/maven-fuzzy-factory-etl)**

</details>

<details>
<summary><b>📈 LinkedIn — the loudest posts weren't the ones that converted</b></summary>

<br>

| | |
|:--|:--|
| **Scope** | 59 organic posts, Jan–Nov 2024 |
| **Finding** | Top-reach topics pulled 8,703 impressions; recap posts pulled 1,209 — and **39.5% engagement**, double the next best |
| **Also** | "Shorter is better" was false: medium posts hit 11.4% CTR vs 3.6% for the shortest |
| **Fixed** | Casing typo splitting one category in two; a "Total" row hiding inside the raw table |

➡️ **[Open the workbook](https://github.com/Plensia/linkedin-content-performance-analysis)**

</details>

<details>
<summary><b>☕ Coffee — stated taste actually survived the blind test</b></summary>

<br>

| | |
|:--|:--|
| **Sample** | 4,023 respondents |
| **Finding** | Same coffee won both: 36.7% stated favourite, 3.38 blind score |
| **Fixed** | Three ordinal charts sorting by count instead of true sequence — nominal ones deliberately left alone |

➡️ **[View the dashboard](https://github.com/Plensia/great-american-coffee-taste-analysis)**

</details>

<details>
<summary><b>🙈 …and the things I got wrong first</b></summary>

<br>

- Transfer velocity looked like an obvious fraud signal. 99.86% of accounts transact exactly once — there's no velocity to measure.
- Wrote a DAX column referencing its own source field. Circular dependency. Moved it to Power Query.
- Assumed a plain text match would sort. Trailing spaces and mixed casing meant every comparison silently failed.

</details>
